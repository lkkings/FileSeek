## Purpose

定义用户如何把文件收入 FileSeek 文件库：从文件管理器右键入口发起，文件被移入受管理目录，并以可查询、可重试的任务形式完成后续索引。

## ADDED Requirements

### Requirement: 文件管理器右键入库入口

系统 **SHALL** 在 Windows、macOS、Linux 三个平台的系统文件管理器右键菜单中提供"添加到 FileSeek 库"入口。该入口 **MUST** 仅在选中项包含至少一个受支持类型的文件时可见。

受支持类型 **MUST** 至少覆盖：文档（PDF、DOCX、TXT、MD）、图片（JPG、PNG、WEBP、GIF、BMP）、视频（MP4、MOV、MKV、AVI、WEBM）。

#### Scenario: 右键受支持的文件

- **WHEN** 用户在文件管理器中右键点击一个 PDF 文件
- **THEN** 右键菜单显示"添加到 FileSeek 库"项

#### Scenario: 右键不受支持的文件

- **WHEN** 用户右键点击一个 `.exe` 文件且选中项中无任何受支持文件
- **THEN** 右键菜单不显示"添加到 FileSeek 库"项

#### Scenario: 多选混合类型

- **WHEN** 用户同时选中 3 个图片、1 个视频和 1 个不受支持的文件并点击入库
- **THEN** 4 个受支持文件各自生成一个入库任务，不受支持的文件被跳过且不产生错误提示

### Requirement: 右键操作不阻塞文件管理器

点击入库后，右键扩展 **MUST** 在 500 毫秒内把控制权交回文件管理器，并且 **MUST NOT** 等待文件移动、特征抽取或索引完成。

#### Scenario: 提交大体积视频

- **WHEN** 用户对一个 5 GB 视频点击入库
- **THEN** 文件管理器立即恢复响应，任务在后台排队处理

#### Scenario: 后端服务未运行

- **WHEN** 用户点击入库且后端服务当前未运行
- **THEN** 系统启动后端服务并提交该任务，用户无需手动启动应用

#### Scenario: 后端服务无法启动

- **WHEN** 后端服务在启动超时窗口内未就绪
- **THEN** 系统向用户显示一条可读的失败提示，说明入库未开始且可稍后重试

### Requirement: 文件移入受管理文件库

入库 **SHALL** 把原文件从原位置**移动**到文件库中按类型划分的目录，而非复制。移动完成后，原路径 **MUST NOT** 仍存在该文件。

系统 **MUST** 为每个入库文件记录其原始路径与库内路径。

#### Scenario: 图片入库

- **WHEN** 用户把 `D:\downloads\cat.jpg` 加入文件库
- **THEN** 文件出现在文件库的图片目录下，`D:\downloads\cat.jpg` 不再存在，且元数据同时记录原始路径与库内路径

#### Scenario: 库内已存在同名文件

- **WHEN** 入库文件的目标文件名与库中已有文件冲突且两者内容不同
- **THEN** 系统为新文件生成不冲突的库内名称并完成入库，不覆盖已有文件

#### Scenario: 移动过程中失败

- **WHEN** 文件移动因权限不足或目标不可写而失败
- **THEN** 任务标记为失败并附带失败原因，原文件保持在原位置不被破坏

### Requirement: 内容去重

系统 **SHALL** 依据文件内容判定重复。当入库文件与库中已有文件内容一致时，系统 **MUST NOT** 在库中产生第二份副本。

#### Scenario: 加入内容重复的文件

- **WHEN** 用户加入一个与库中已有文件内容完全一致的文件
- **THEN** 系统不新增库内副本，向用户说明该文件已存在，并把该次提交的原始路径追加到已有记录

#### Scenario: 同名但内容不同

- **WHEN** 用户加入一个与库中文件同名但内容不同的文件
- **THEN** 两个文件都被保留为独立条目

### Requirement: 入库任务队列与进度

每次入库 **SHALL** 产生一个可查询的任务。任务状态 **MUST** 取自：排队中、处理中、已完成、失败。处理中的任务 **MUST** 暴露 0 到 100 的进度值。

任务记录 **MUST** 持久化，使其在后端服务重启后仍可查询。

#### Scenario: 查询任务进度

- **WHEN** 客户端查询一个处理中的视频入库任务
- **THEN** 返回该任务的状态与进度百分比

#### Scenario: 服务重启后恢复

- **WHEN** 后端服务在有任务排队时被重启
- **THEN** 未完成的任务在服务恢复后继续处理，不丢失

### Requirement: 失败任务可重试

失败的任务 **SHALL** 保留失败原因并允许重新执行。重试 **MUST NOT** 要求用户重新在文件管理器中选择文件。

#### Scenario: 重试失败任务

- **WHEN** 用户对一个因 NAS 断连而失败的任务发起重试
- **THEN** 系统重新执行该任务，成功后状态变为已完成

#### Scenario: 部分完成后失败

- **WHEN** 一个视频任务在完成抽帧后于索引阶段失败并被重试
- **THEN** 系统复用已完成阶段的结果，不重复执行已完成的抽帧工作

### Requirement: 并发上限

系统 **SHALL** 限制同时处理的入库任务数量，以避免耗尽内存与显存。该上限 **MUST** 可由用户配置。

#### Scenario: 提交超过上限的任务

- **WHEN** 用户一次性提交 50 个视频且并发上限为 3
- **THEN** 同一时刻最多 3 个任务处于处理中，其余保持排队中

### Requirement: 用户主动提交的任务优先

系统 **SHALL** 让用户通过右键单次提交的任务优先于批量导入产生的任务被处理。

#### Scenario: 批量导入期间的单次提交

- **WHEN** 批量导入 200 个文件的过程中，用户右键提交 1 个新文件
- **THEN** 该新文件在当前处理中的任务完成后即被处理，不排在 200 个文件之后

## Purpose

定义入库文件如何被转换为可检索的表示：三类媒体各自抽取什么内容、视频如何切分为可定位的片段与关键帧，以及模型规模如何随用户硬件自动调整。

## ADDED Requirements

### Requirement: 本地推理

所有特征抽取与向量化 **MUST** 在用户设备上完成。系统 **MUST NOT** 为索引或检索目的把文件内容、抽取文本或向量传输到外部服务。

模型权重的下载是唯一允许的对外网络访问，且 **MUST** 仅在用户同意后发生。

#### Scenario: 索引期间的网络行为

- **WHEN** 系统索引一批文档与图片
- **THEN** 不产生任何携带文件内容或向量的对外请求

#### Scenario: 离线环境索引

- **WHEN** 设备处于离线状态且所需模型权重已就位
- **THEN** 索引正常完成

### Requirement: 硬件自适应模型选择

系统 **SHALL** 在首次启动时检测可用计算硬件，并据此选择模型规模：检测到具备足够显存的 GPU 时使用高精度模型，否则使用可在 CPU 上运行的轻量模型。

用户 **MUST** 能够覆盖自动选择结果，强制使用 GPU、强制使用 CPU 或指定模型规模。

系统 **MUST** 向用户展示当前生效的模型与计算设备。

#### Scenario: 检测到可用 GPU

- **WHEN** 设备具备可用 GPU 且显存满足高精度模型要求
- **THEN** 系统选择高精度模型并在设置中显示当前使用 GPU

#### Scenario: 无可用 GPU

- **WHEN** 设备无可用 GPU
- **THEN** 系统选择轻量模型并在设置中显示当前使用 CPU

#### Scenario: 用户强制使用 CPU

- **WHEN** 用户在具备 GPU 的设备上强制选择 CPU
- **THEN** 后续索引与检索均在 CPU 上执行

#### Scenario: 显存不足以加载所选模型

- **WHEN** 加载高精度模型时显存不足
- **THEN** 系统降级到轻量模型并告知用户已降级及其原因，而非让索引失败

### Requirement: 同一库内的向量兼容性

系统 **MUST** 保证同一向量索引中的所有向量来自同一模型。当生效模型发生变更时，系统 **MUST** 阻止把新模型产生的向量混入旧索引，并向用户提供重建索引的途径。

#### Scenario: 用户切换模型规模

- **WHEN** 用户把模型规模从轻量切换为高精度
- **THEN** 系统提示已有索引需重建，并在用户确认前不混合写入新向量

### Requirement: 文档索引

对文档，系统 **SHALL** 抽取可读文本并为其生成可用于自然语言检索的向量表示。

系统 **MUST** 记录抽取到的文本，使检索结果能够呈现匹配上下文。

超出单次向量化长度上限的文档 **MUST** 被分段处理，而非截断丢弃其余内容。

#### Scenario: 索引 PDF 论文

- **WHEN** 一篇多页 PDF 论文入库
- **THEN** 其正文被抽取、分段并向量化，该文档可通过描述其主题的自然语言查询命中

#### Scenario: 扫描版 PDF 无可抽取文本

- **WHEN** 一个 PDF 不含文本层
- **THEN** 系统对其页面执行文字识别以获得文本，若仍无可用文本则把该文件标记为仅可按文件名检索

#### Scenario: 加密或损坏的文档

- **WHEN** 文档因加密或损坏无法被解析
- **THEN** 任务标记为失败并附原因，文件仍保留在库中

### Requirement: 图片索引

对图片，系统 **SHALL** 生成可与自然语言查询直接比对的视觉向量表示，使用户能用描述画面内容的语句检索图片。

系统 **SHALL** 额外对图片执行文字识别，并把识别出的文本纳入可检索内容。

#### Scenario: 按画面内容检索图片

- **WHEN** 用户查询"图中带有猫的图片"
- **THEN** 画面中包含猫的已入库图片出现在结果中

#### Scenario: 按图中文字检索图片

- **WHEN** 一张截图中包含"深度学习"字样且用户查询该词
- **THEN** 该截图出现在结果中

#### Scenario: 无法解码的图片

- **WHEN** 图片文件损坏无法解码
- **THEN** 任务标记为失败并附原因

### Requirement: 视频片段级索引

对视频，系统 **SHALL** 按固定时间间隔采样画面，并把内容连续的相邻采样聚合为片段。每个片段 **MUST** 携带起止时间与自身的向量表示。

检索 **MUST** 能定位到片段而非仅定位到整个视频文件。

#### Scenario: 索引十分钟视频

- **WHEN** 一个 10 分钟视频入库
- **THEN** 系统产出多个带起止时间的片段，每个片段都可被独立检索命中

#### Scenario: 按片段内容检索视频

- **WHEN** 用户查询"视频中出现过红色头发的女孩"
- **THEN** 结果给出命中视频及其内出现该内容的片段起止时间

#### Scenario: 同一视频多处命中

- **WHEN** 目标内容在一个视频中的三个不同时段出现
- **THEN** 该视频的结果包含三个片段，各自带有独立的起止时间与相似度

#### Scenario: 视频无法解码

- **WHEN** 视频容器或编码无法被解码
- **THEN** 任务标记为失败并附原因

### Requirement: 片段关键帧缩略图

系统 **SHALL** 为每个视频片段生成一张关键帧缩略图并持久化，供检索结果直接展示。

缩略图 **MUST** 可被客户端按片段标识取得，且 **MUST NOT** 要求客户端为展示缩略图而读取原视频文件。

#### Scenario: 展示片段缩略图

- **WHEN** 检索返回一个视频片段
- **THEN** 客户端可取得该片段的关键帧缩略图用于展示

#### Scenario: NAS 不可达时展示缩略图

- **WHEN** 缩略图已被本地缓存而 NAS 当前不可达
- **THEN** 客户端仍能展示该缩略图

### Requirement: 索引进度与阶段可见

索引过程 **SHALL** 向调用方暴露当前阶段与进度，使用户能区分文件移动、特征抽取、索引写入等阶段。

#### Scenario: 观察视频索引进度

- **WHEN** 用户查看一个正在索引的视频任务
- **THEN** 显示其当前阶段与进度百分比，且进度在处理过程中单调递增

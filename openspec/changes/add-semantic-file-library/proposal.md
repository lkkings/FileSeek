## Why

用户积累的文档、图片、视频散落在各个目录中，只能靠文件名和目录结构回忆内容，无法用"图中带猫的图片""关于深度学习的论文"这类自然语言找回。现有云端方案要求上传原文件，隐私成本高，且无法处理已有的本地/NAS 存量文件。

FileSeek 提供一个跨平台桌面产品：右键即可把文件收入受管理的文件库，全部 AI 推理在本地完成，用自然语言检索三类媒体，视频可直接定位到出现目标内容的片段。

## What Changes

- 新增跨平台右键菜单入口（Windows Shell Extension、macOS Finder Sync Extension、Linux Nautilus/Dolphin/Thunar 插件），一次点击把文件移入文件库
- 新增本地常驻后端服务（HTTP API + 托盘图标），负责入库、索引、检索；右键扩展仅做轻量 HTTP 调用，不阻塞文件管理器
- 新增受管理的文件库目录结构：按类型分文件夹存放，原文件被**移动**而非复制，移动前后路径均记入元数据
- 新增本地 AI 索引管线：文档抽取文本 + 文本向量、图片 CLIP 向量 + OCR、视频抽帧 + 片段级向量 + 关键帧缩略图
- 新增硬件自适应模型选择：检测 GPU 可用性与显存，自动在大/小模型之间取舍，无 GPU 时降级到 CPU 轻量模型
- 新增自然语言检索：Faiss 向量检索 + SQLite 元数据联查，结果按文件类型分组；视频结果返回匹配片段的时间区间、相似度与关键帧缩略图，点击跳转到该片段播放
- 新增 NAS 接入（模式 B）：文件库位于 NAS 挂载点，向量索引与元数据库保存在本地；支持 mDNS 自动发现与手动配置，含连接健康检查与断线提示
- 新增任务队列与进度反馈：入库任务持久化、可重试、可查询进度，并发受限以避免占满内存与 GPU

无 **BREAKING** 变更（全新项目，无既有行为可破坏）。

## Capabilities

### New Capabilities

- `file-ingestion`: 右键入库入口、文件移入库、去重、入库任务队列与进度/失败重试语义
- `library-storage`: 文件库目录布局、SQLite 元数据模型、Faiss 索引持久化、NAS 模式 B 挂载/自动发现/健康检查
- `media-indexing`: 文档/图片/视频的特征抽取与向量化管线、视频片段切分与关键帧缩略图、硬件自适应模型选择
- `semantic-search`: 自然语言查询解析、跨类型向量检索与排序、视频片段级结果结构
- `desktop-client`: 桌面应用界面（搜索、结果呈现、片段跳转播放）、托盘常驻与后端生命周期管理、库与 NAS 的设置界面

### Modified Capabilities

无（项目尚无既有 spec）。

## Impact

- **新增代码**：桌面客户端（Tauri + React/TypeScript）、Python 后端服务（FastAPI）、三套平台原生右键扩展（Rust/Swift/Python-GObject）
- **新增依赖**：faiss、torch、open-clip、sentence-transformers、Tesseract/PaddleOCR、ffmpeg/PyAV、zeroconf；打包侧需处理模型权重分发与首次启动下载
- **数据**：新增本地 SQLite 元数据库与 Faiss 索引文件；文件库目录可位于本地或 NAS 挂载点
- **系统集成**：平台级右键菜单注册、开机自启/后台服务、本地回环 HTTP 端口、NAS 凭据经系统密钥链存储
- **性能约束**：视频索引为计算密集型，需队列化与并发上限；无 GPU 环境下需明确的降级预期
- **打包分发**：安装包体积受模型权重影响，需决定内置或按需下载；右键扩展在各平台的安装/签名要求不同

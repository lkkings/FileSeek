## Context

搜索请求已返回 `items`、`total`、`page_size` 和 `page_number`，页面默认每页 20 条，但 `useFileSearch` 只固定请求第一页，结果组件在当前页内本地排序并渲染分类 Tab。项目已经有共享的 `Pagination`、`BatchOperationsBar`、`DeleteConfirmDialog`、`MoveFilesDialog`、`FileDetailDrawer`，以及批量移动到回收站和文件夹的前端服务调用。文件夹详情页也已有可复用的表格行交互和视觉样式。

## Goals / Non-Goals

**Goals:**

- 让搜索结果页成为可分页、可批量管理文件的完整工作区。
- 复用文件夹详情页和全局共享组件，避免复制交互和样式。
- 保持搜索结果的单列布局和文件夹表格行视觉一致性。

**Non-Goals:**

- 不新增或修改后端搜索、移动文件、回收文件接口。
- 不修改高级筛选中的文件类型筛选能力。
- 不实现搜索结果跨页保留选择。

## Decisions

1. **删除搜索结果页 Tab，保留高级筛选**

   `SearchResultsView` 不再接收文件类型 Tab 的状态和回调，也不再从当前页计算分类数量。文件类型仍由 `AdvancedFilters` 控制，搜索结果只展示当前过滤条件返回的数据。

2. **复用并泛化文件表格行**

   将文件夹详情页的表格行交互抽为共享行组件，或在其现有组件上补齐 `modified` 展示并允许搜索页复用。行内仍保留批量选择、长按、单击、双击等回调；搜索页用单列容器约束布局，并复用预览、文件名、标签和尺寸的视觉 token。这样文件夹详情页与搜索结果页不会长期维护两套文件行实现。

3. **搜索状态由搜索 hook 统一维护**

   `useFileSearch` 增加页码和每页数量状态，并把当前排序参数纳入每次搜索请求。`submitSearch` 支持指定页码，页面切换时保持查询词、高级筛选、排序、文件夹范围和页大小不变。搜索结果组件只负责展示并触发 `onPageChange`，由父页面或搜索 hook 发起新请求。

4. **复用共享分页组件**

   使用现有 `Pagination` 的 `details` 视觉变体。总页数由 `total / page_size` 计算，当前页由响应数据或受控页码计算。批量操作导致当前页变空时，将页码调整到仍存在的最大页并重新请求，最低保留第一页。

5. **复用批量操作交互链**

   `LibraryPage` 继续持有 `useMoveFilesToRecycle` 和 `useMoveFilesToFolder`，向 `SearchResultsView` 传入两个操作回调和文件夹列表。搜索页复用 `BatchOperationsBar`、`DeleteConfirmDialog` 和 `MoveFilesDialog`。如果搜索范围是某个文件夹，移动目标列表排除该文件夹；全局搜索不排除任何文件夹。

6. **复用文件详情抽屉**

   非批量模式下单击结果行打开现有 `FileDetailDrawer`。抽屉中的打开操作沿用 `LibraryPage` 现有 `onOpenFile` 流程，保持访问记录和文件打开行为一致。双击预览不在本次范围内改动，除非现有共享行组件需要保留其双击回调。

## Risks / Trade-offs

- [共享行组件改动影响文件夹详情页] → 在复用前保留文件夹详情页现有 props 和默认行为，为搜索页新增布局/字段能力时补齐两侧测试。
- [批量操作后当前页变空] → 根据刷新后的 `total` 和 `page_size` 计算最近的有效页并自动重新请求。
- [移动目标排除逻辑与搜索范围不一致] → 明确以搜索发起时的文件夹范围为准：范围内搜索排除该文件夹，全局搜索不排除。
- [排序状态与请求参数不一致] → 将排序状态提升到搜索请求状态中，禁止仅在当前页本地排序。

## Migration Plan

1. 先抽出或泛化共享文件行并验证文件夹详情页现有行为不变。
2. 接入搜索页单列布局、详情抽屉和分页。
3. 接入批量回收和批量移动交互。
4. 更新组件测试后合并；如需回滚，可按组件拆分逐步回退，不涉及数据迁移。

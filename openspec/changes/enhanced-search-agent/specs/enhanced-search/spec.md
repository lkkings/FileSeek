## Purpose

Provides a retrieval-augmented search mode that uses a configured external retrieval expert to plan multiple searches, select real file IDs, and return results in the existing search contract.

## ADDED Requirements

### Requirement: Activate retrieval augmentation
The system SHALL provide a **启动检索增强** toggle in the search bar. Retrieval augmentation MUST default to off, and the advanced filter controls MUST be visible only while it is off.

#### Scenario: Enable retrieval augmented mode
- **WHEN** the user activates the toggle
- **THEN** the search input remains available for a natural-language request
- **AND** the advanced filter controls are hidden

#### Scenario: Disable retrieval augmented mode
- **WHEN** the user deactivates the toggle
- **THEN** the user can reopen and use the existing advanced filter controls

### Requirement: Configure the retrieval agent
The system SHALL store OpenAI-compatible agent settings locally in the backend database. The settings MUST include the base URL, API key, and model name required for Chat Completions. The API key MUST NOT be returned in full by a settings read endpoint.

#### Scenario: Save agent settings
- **WHEN** the user saves a non-empty base URL, API key, and model name
- **THEN** the backend persists the settings locally
- **AND** subsequent settings reads indicate that the API key is configured without returning its full value

#### Scenario: Agent settings are incomplete
- **WHEN** any required agent setting is missing
- **THEN** retrieval-augmented search is unavailable
- **AND** the user is directed to complete the agent settings before retrying

#### Scenario: Test agent settings
- **WHEN** the user tests a configured base URL, model, and API key
- **THEN** the system performs an OpenAI-compatible Chat Completions request
- **AND** the settings interface reports whether the connection succeeded without exposing the API key

### Requirement: Send natural language to a retrieval expert
The system SHALL send the user's natural-language request to a retrieval expert agent using OpenAI-compatible Chat Completions with tool calling. The agent MUST be allowed to call the search tool more than once.

#### Scenario: Agent refines its query
- **WHEN** the first search-tool result does not sufficiently match the user's description
- **THEN** the agent may issue another search-tool call with different parameters
- **AND** the backend executes each valid call against the existing search behavior

### Requirement: Preserve the search tool contract
The retrieval agent's search tool input contract MUST match the existing search API query and filter parameters, excluding `folder_id`, pagination, and sorting. `folder_id` MUST be supplied by the enhanced-search request rather than the agent.

#### Scenario: Agent calls the search tool
- **WHEN** the agent invokes the search tool
- **THEN** the accepted parameters cover the existing query and filter behavior without `folder_id`, pagination, or sorting
- **AND** the backend executes the search using those parameters and the frontend-supplied folder scope

### Requirement: Filter results by verified IDs
The final retrieval-augmented result set MUST contain only records whose file IDs were both selected by the agent and returned by at least one search-tool result. The system MUST NOT return file records generated by the agent.

#### Scenario: Agent submits verified IDs
- **WHEN** the agent submits IDs that appeared in prior search-tool results
- **THEN** the final results contain the corresponding real records

#### Scenario: Agent submits an unverified ID
- **WHEN** an agent-submitted ID did not appear in any search-tool result
- **THEN** that ID is excluded from the final results

### Requirement: Preserve search response and pagination behavior
Retrieval-augmented search MUST return the same response structure as the existing search API and MUST support the existing pagination interaction. The total, counters, page metadata, and has-more flag MUST be derived from the final verified result set.

#### Scenario: Paginate cached retrieval results
- **WHEN** the user changes page after a retrieval-augmented search has completed
- **THEN** the system returns the requested page without invoking the external agent again while the aggregation remains valid

#### Scenario: Return an empty result
- **WHEN** the agent produces no verified file IDs
- **THEN** the response is a valid empty search response

### Requirement: Report enhanced-search failures
The system SHALL surface agent configuration, provider, timeout, and malformed-tool-call errors as actionable search failures without exposing the API key.

#### Scenario: Provider request fails
- **WHEN** the Chat Completions request returns an error or times out
- **THEN** the user receives a search failure message
- **AND** no partial unverified result is presented as a successful search

### Requirement: Prevent duplicate search submissions
The system SHALL show a loading state while a search request is pending. Search controls MUST prevent duplicate submissions during that state.

#### Scenario: Search is pending
- **WHEN** a search request is pending
- **THEN** the search area shows a loading indicator
- **AND** the search input and mode/filter controls are disabled
- **AND** repeated submit actions do not create another search request

## Purpose

把文件导入时的解析、向量化、OCR 和分类计算放到独立的子进程中执行。原生层崩溃或内存耗尽时只影响当前任务，API 服务保持可用，空闲时交还全部模型内存。

## ADDED Requirements

### Requirement: 导入计算在独立进程中执行
系统 SHALL 在独立于 API 服务进程的导入模型进程中执行文件的解析、向量化、OCR 和分类计算。API 服务进程 SHALL NOT 为导入任务加载任何推理模型。

#### Scenario: 处理文档时 API 进程不加载模型
- **WHEN** 用户导入一个文档文件，任务开始处理
- **THEN** 解析和向量化在导入模型进程中执行
- **AND** API 服务进程的内存中不存在推理模型会话

### Requirement: 导入进程崩溃不影响服务
导入模型进程异常退出（非 0 退出码或被信号终止，包括内存耗尽被系统杀掉）时，API 服务 SHALL 继续运行并响应请求。当时正在处理的任务 SHALL 被标记为失败，失败原因 SHALL 说明是处理进程异常退出，并包含退出码或信号。

#### Scenario: 处理过程中导入进程被系统杀掉
- **WHEN** 某个任务处理期间，导入模型进程被 SIGKILL 终止
- **THEN** 该任务状态变为失败，失败原因说明处理进程异常退出（可能内存不足）
- **AND** API 服务进程仍在运行，搜索、文件库等接口正常响应

#### Scenario: 原生库触发 abort
- **WHEN** 导入模型进程内的原生库调用 abort 导致进程以 SIGABRT 退出
- **THEN** 当前任务被标记为失败，API 服务不受影响

### Requirement: 导入进程按需重启
导入模型进程不存在时（崩溃、空闲退出或尚未启动），系统 SHALL 在领取到下一个待处理任务时自动启动它。崩溃前排在队列中的其他任务 SHALL 在进程重启后继续处理。

#### Scenario: 崩溃后继续处理队列
- **WHEN** 队列中有 3 个任务，处理第 1 个时导入模型进程崩溃
- **THEN** 第 1 个任务被标记为失败
- **AND** 系统重新启动导入模型进程，并继续处理第 2、3 个任务

### Requirement: 导入进程空闲退出
导入模型进程在连续空闲时间达到 `task_worker_idle_timeout`（默认 5 分钟）后 SHALL 自行正常退出，交还全部内存。配置为 0 时 SHALL 不因空闲退出。空闲退出 SHALL NOT 被视为崩溃，也 SHALL NOT 影响任何任务的状态。

#### Scenario: 导入结束后空闲退出
- **WHEN** 最后一个任务完成后，超过 `task_worker_idle_timeout` 没有新任务
- **THEN** 导入模型进程以正常状态退出
- **AND** 不产生任何失败任务或错误日志

#### Scenario: 关闭空闲退出
- **WHEN** `task_worker_idle_timeout` 配置为 0
- **THEN** 导入模型进程在空闲时保持运行

### Requirement: 终止任务立即生效
用户终止正在处理的任务时，系统 SHALL 在数秒内停止该任务的计算，即使计算正卡在单次长时间推理中也不例外。被终止任务已写入的部分向量 SHALL 被清理，任务状态 SHALL 变为已终止。

#### Scenario: 长推理期间终止任务
- **WHEN** 任务正在执行一次耗时较长的向量化批次，用户点击终止
- **THEN** 该任务的计算在数秒内停止，状态变为已终止
- **AND** 该任务写入的向量被删除，之后的任务可以正常处理

### Requirement: 存储只由服务进程写入
向量索引和数据库 SHALL 只由 API 服务进程写入。导入模型进程 SHALL 只返回计算结果（文本块、向量、标签），SHALL NOT 直接打开或写入向量索引和数据库。

#### Scenario: 导入与回收站删除同时进行
- **WHEN** 一个导入任务正在写入向量，同时用户在回收站彻底删除文件
- **THEN** 两个写入操作都在 API 服务进程内完成，不出现跨进程并发写同一存储的情况

### Requirement: 进度持续上报
导入任务在独立进程中执行时，系统 SHALL 继续按阶段上报进度（抽取、编码、分类、索引），前端看到的进度粒度和行为 SHALL 与改造前一致。

#### Scenario: 大文档进度可见
- **WHEN** 处理一个包含数百个文本块的文档
- **THEN** 任务的编码进度随批次逐步增长，而不是一直停在 0 直到结束
